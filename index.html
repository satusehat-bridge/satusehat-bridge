Arsitektur & Perlindungan Data

Bagaimana SATUSEHAT Bridge Bekerja?

Pemisahan fisik tegas antara basis data internal SIMRS dan server Kemenkes. Tidak ada perubahan struktur tabel produksi rumah sakit.

1. Table Adapter Staging

SIMRS cukup melakukan INSERT baris data ke tabel staging terpisah (satusehat_bridge_staging_envelope). Mendukung Microsoft SQL Server 2008+, MySQL 5.7+, dan PostgreSQL 12+.

Nol modifikasi DDL tabel rekam medis SIMRS

2. Core Kanonikal & 49 Tabel

Mesin internal memvalidasi skema, memetakan terminologi (ICD-10, LOINC, SNOMED, KFA), mengenkripsi rahasia dengan AES-256-GCM, dan mengantrekan pengiriman secara asinkron dengan kontrol konkurensi (lease lock).

Idempotensi ketat & anti duplikasi pengiriman

3. Outbound Worker Delivery

Pekerja latar belakang (Queue Worker) mengubah entitas menjadi bundle FHIR R4 resmi Kemenkes DTO, menangani rotasi token OAuth2 otomatis, serta mencatat status HTTP dan audit log pengiriman.

Retry eksponensial cerdas jika Kemenkes down
